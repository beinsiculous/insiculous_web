# Data model

Canonical files live in `data/` (edit these), derived files in `build/` (never edit).
Schemas in `data/schema/` are JSON Schema 2020-12 and double as field documentation;
`scripts/fk_core/validate.py` enforces the subset it understands plus cross-file rules.

## Conventions
- ids: lowercase kebab-case, immutable. Renaming = new id + note, never a silent change.
- times `"HH:MM"` (24h; `"24:00"` only as a block end), dates `YYYY-MM-DD`, durations integer minutes.
- Every imported record keeps `raw` (original cells) and `sourceRow`; keep them when editing.
- Field names are human-readable, no abbreviations.

## Canonical files
| file | top-level shape | notes |
|---|---|---|
| `meta.json` | `schemaVersion, cycleLengthDays, epoch{date,dayKey}, timezone` | `epoch` is a fallback anchor; default resolution is season-anchored |
| `seasons.json` | `seasons[]` of `{id,name,gregorianRange,durationWeeks,startRule{kind,month?,day?,weekday?,occurrence?,term?,index?,offsetDays,snap{weekday,direction}|null},startDescription,startDayKey,seasonMode,outdoorWindow{uvAbove4},focus[],menuId,knownStarts,raw}` | start dates computed from `startRule` by `fk_core/dates.py` `start_date_for_rule` (`docs/domain.md`); `knownStarts` is a check value the validator verifies |
| `days.json` | `order[14]`, `days{dayKey → {index,week,weekday,variant,label,shortKey,mainFocus,blockFocus{early?,midday?,late?},appointmentBlock}}` | focus values are category keys or `flexible`; on the neutral canonical data `mainFocus` is `null` and `blockFocus` is `{}` (a person's grid comes from their applied import) — the workbook example set fills them |
| `blocks.json` | `order[5]`, `blocks{key → {label,start,end,durationMinutes,mealPrimary,mealSecondary,carriesFocus}}` | |
| `categories.json` | `order[7]`, `categories{key → {label,subjects[]}}`, `flexibleFocus`, `subjects{key → {label,category,description?}}` | `description` = what the subject covers (PR includes social media, coaching includes parenting) |
| `activities.json` | `activities[]` of `{id,title,dayKey,block,priority,categories[],flexibility,timing|null,detail,raw}` | `id = slug(title)--dayKey--block[--n]`; **empty** on the neutral canonical data (the workbook example set has 64) |
| `menus/<season>.json` | `{id,seasonId,notes[],meals[{id,slot,number,mealKey,days[],menu,cookExtra,raw}]}` | one file per season; **none** on the neutral canonical data (the workbook example set has `spooky-season`) |
| `weights.baseline.json` | see `docs/weights.md` | lives in `examples/workbook/` only — generated by `analyze_allocations.py --overlay examples/workbook`; the neutral bundle has `weights: null` |
| `weights.<id>.json` | same shape, `source: "questionnaire"`, plus `proposal` (the generator's grid, `docs/generator.md`) | optional; questionnaire output dropped in for validation, not bundled |
| `schema/import.schema.json` | import document `{schemaVersion (2), source{kind,description,importedAt}, commitments[], tasks[], skipped[], review[], + machine sections standingAppointments[], fixedActivities[], blockFocusGrid, appointmentBlocks, blocks[], meals[], mealPlan{items[]}, notes[]}` | not a data file — the contract importers emit and the Assistant page accepts (`docs/importers.md`); Fork Knife writes one (`docs/meal-plan.md`) |
| `schema/meal-plan.schema.json` | meal-plan document `{schemaVersion (1), kind: "meal-plan", source?, items[{meal, dish, days[1–2], notes?}], notes[]?}` | the fortnight menu an assistant (or the person) hands Fork Knife (`docs/meal-plan.md`) |
| `schema/keep.schema.json` | a keep — see `docs/keep-format.md`, which is the format's specification and the only description of its shape with tests behind it | not a data file — the fortnight a visitor loads from their own device. **Open on purpose**: no object forbids extra properties, because adding a field is not a version bump (the `menu` section arrived that way on 2026-08-29). Byte-copied into the private app repo; `tests/test_keep.py` compares them |
| `questionnaire.json` | `schemaVersion, wantMoreMultiplier, wakingWindow{default{start,end},minutes{min,max,step},track{start,minutes}}, blockSplit{standoutMultiplier,maxFocusBlocks,cutGridMinutes,cutSearchMinutes,straddlePenalty,edgeBonus,focusBlockKeys}, generator{anchorPinCoverage,overshootSlackCells,preferredBlockWeight,energyPeakWeight,seasonFocusWeight,alternationWeight,energyPeakBlock,sessionGridMinutes,maxSessionMinutes,practiceMinutes,mealMinutes,mealSlotTimes}, essentialCategories{min,max}, mealsPerDay, slotsPerMeal, mealPrep{minutes{min,max,step},defaultPrepMinutes,defaultCookMinutes}, yearSections, options{mealSlots, yearSplitSchemes[{id,label,sections,sectionLabel,template[],templateFrom?}], sectionMarkers, startRuleKinds, solarTerms, snapDirections, startVariants, weekdays, appointmentCadences[{id,label,needs}], nthChoices, practices, agendaScopes, energyPeaks}, defaultAnswers{sentiment,delegable,essential,meals,yearSplitScheme,weekStart,standingAppointments,appointmentWeekdays,practices,agendaScope,restDays,energyPeak,context}, subjectSliders{subject → {minutesPerDay{min,max}, default{min,max}, peripheralByDefault, moreMax, step}}, sections[{id,title,intro,questions[{id,kind,prompt,note,…}]}]` | question definitions the app renders from; see `docs/questionnaire.md` |

## Derived files (`build/`)
| file | content |
|---|---|
| `derived/menuByDay.json` | `{dayKey → {brunch,snack,dinner → {mealId,menu,cookExtra}}}` — `{}` without a menu (neutral data); the workbook's Menu sheet on the example set |
| `derived/planByDay.json` | `{dayKey → {label,mainFocus,appointmentBlock,menu,blocks[{block,start,end,focus,isAppointmentBlock,activities[…+mealPrepTargets]}]}}` — the data set's own plan (empty blocks on the neutral data); the Astro day pages render the person's profile instead |
| `derived/allocations.json` | `focusWindow`, `byBlockFocus`, `byActivities` — minutes and shares per category/day/block of the data set (all flexible / zero on the neutral data) |
| `derived/defaultImport.json` | the data set as an import document (`data/schema/import.schema.json`) — the example import document (applied on the Assistant page): on the neutral data FortKnight's empty version-2 example (`source.kind: other`, empty commitments/tasks/skipped, a review line); on the workbook example set the workbook itself (`source.kind: xlsx`) (`docs/importers.md`) |
| `fortknight.bundle.json` | everything above in one object with `buildInfo.buildHash`; what the app loads |

## Edit loop
1. Edit `data/…`. Keep `raw`; add structured fields beside it.
2. `python3 scripts/validate.py` — fix every ERROR; read WARNINGs.
3. `python3 scripts/build.py` — regenerates `build/`.
4. `python3 -m unittest discover tests`.

## Adding things
- **A new season menu**: copy `menus/spooky-season.json`, change `id`/`seasonId`, set the season's `menuId`. Every day must get exactly one brunch/snack/dinner.
- **A new activity**: append to `activities[]` with a fresh id; `timing: null` for block-scoped routines; `detail.raw` always present.
- **A new category**: is a schema change — update `fk_core/keys.py`, `categories.schema.json`, and this doc together.
- **A new subject**: add it to `categories.json` (`categories[*].subjects` and `subjects`) **and** give it a slider in `questionnaire.json` — `validate.py` errors on a subject without one.
